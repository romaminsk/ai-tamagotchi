# Оптимизация локальной LLM (ai-tamagotchi)

Дата: 2026-10-08T16:04:54 · Ollama: ollama version is 0.34.4

## Цель

Подобрать параметры и промпт для qwen2.5-3B так, чтобы реплики питомца могли быть объёмными без потери скорости; честно сравнить baseline и оптимизации и вынести управление параметрами в UI.

## Методика

- 6 фиксированных сценариев: fed, play, clean, wake, настроение «голодный», настроение «грустный».
- Прогрев: 1 запрос на конфигурацию (не в статистике). Холодный старт: один раз `ollama stop` и первый запрос (load_duration отдельно).
- Прогонов: перемер: один запуск; 2 прогона × 6 сценариев на конфигурацию (12 замеров); первый warmup — холодный старт; порядок конфигураций перемешан и зафиксирован `random.Random(42)` (полный shuffle: ; фактический порядок запуска: B, D-q8_0, E-2048, C, M-medium, A, E-8192).
- Автометрики качества — прокси: не заменяют человеческую оценку.
Все данные одного запуска (перемер, 1712 c), кроме q2_K-prior — прошлый запуск.

## Правило выбора OPTIMIZED
Итог: `B`
Обоснование: пороги прошли: A,B,M-medium; chars/sec в пределах 10%; взят более длинный: B

Примечание: Правило выбора заменено после первого запуска бенчмарка: раньше было «время <= 2.5×A; самая длинная реплика», сейчас — «доля принятых >= 90% И среднее время <= 15 с; максимум символов в секунду; при равенстве в пределах 10% — более длинная». Причина: порог 2.5×A недостижим для объёмных реплик по построению (A — short 25 симв, long-режимы — 390–430 симв), правило бы всегда возвращало baseline.
Записанный пресет OPTIMIZED (modelsettings.py): temperature=1.0, top_p=0.95, top_k=40, repeat_penalty=1.1, max_tokens=60, num_ctx=4096, length_mode=long, model=qwen2.5:3b, prompt_variant=optimized

## Ограничения

- Одна модель семейства 3B на одном компьютере; малая выборка (12–18 ответов на конфигурацию).
- Автометрики (принимаемость, уникальность, доля кириллицы) — только прокси качества.
- Пиковый RSS — суммарный по всем процессам ollama на машине во время запросов (ps, шаг 0,5 с).
